**DEMO MODE - synthetic data.**

## How to use

I haven't seen a rehearsal yet, so this is a template, not a list of findings. During one rehearsal, note what is confusing, slow, or unreadable. Send the filled log to Person 1, who decides QA priority and passes UI issues to Person 2 (teacher UI) or Person 3 (student UI).

## Things to watch (not observations)

- Is text readable from the back of a room or on a shared screen?
- Does any wait feel longer than a few seconds? Say what the presenter can do during it.
- Is it clear when the teacher, and not the AI, is acting?
- Is the DEMO MODE - synthetic data label visible on every screen?
- Does the before/after metric on screen match what the presenter says?
- Does anyone see a student name or answer that shouldn't be shown?

## Backup checklist

- [ ] Backup speaking notes: `speaking_notes.md` shared with the whole team
- [ ] Screen recording of a full clean run (with a label showing DEMO MODE - synthetic data)
- [ ] Run steps: written by Person 1, since I don't know the live setup
- [ ] Reset steps: written by Person 1, so the demo can be re-run from the start
- [ ] At least two people other than me know how to run and reset the demo
